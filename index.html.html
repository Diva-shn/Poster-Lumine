1. Ruang Lingkup & Batasan Kritis Sistem

Kelompok kami membatasi ruang lingkup aplikasi Lumine agar tidak masuk ke ranah medis riil atau memberikan diagnosis klinis secara mandiri (NF-4 & NF-6). Kami memasang logika pengaman otomatis di sistem:

Jika sub-proses evaluasi risiko (Proses 7.1) mendeteksi skor indikasi kecemasan atau depresi pengguna dari hasil analisis sentimen mencapai batas kritis (≥ 70), fitur curhat mandiri dikunci sementara dan sistem langsung memicu rujukan kontak psikolog profesional.

2. Inklusivitas Aktor Tunanetra

Untuk mengakomodasi kebutuhan interaksi teman-teman tunanetra, kami menerapkan pola desain antarmuka berbasis komponen mandiri:

  • Anotasi Elemen ARIA: Semua form input dan slider penilaian mood harian ditanami tag deskripsi teks tersembunyi agar terbaca sempurna oleh aplikasi Screen Reader bawaan handphone.
  • Asynchronous Voice Input: Input rekaman suara pengguna dikemas dalam protokol stream lokal terlebih dahulu untuk dibersihkan dari noise sebelum dikirim sebagai teks siap pakai ke backend.

5. Alasan Pemilihan Komponen Utama

  • Sisi Backend (Node.js): Kami memilih teknologi ini karena penanganan arsitektur non-blocking I/O nya sangat efisien. Sistem tidak akan mengalami lag atau hang saat menunggu respon antrean API dari server pihak ketiga (LLM), sehingga target performa NF-2 tetap aman.
  • Sisi Frontend (React.js): Memudahkan pengelolaan komponen antarmuka yang dinamis, khususnya untuk memperbarui grafik tren kesehatan mental secara real-time pada halaman Insight pengguna.

6. Penanganan Risiko & Kepatuhan Hukum

Optimasi Batasan Hardware: Muncul kendala performa rendering animasi latihan pernapasan (FR-13) pada handphone RAM di bawah 2 GB. Solusi kami adalah mengganti format video atau GIF berat dengan rendering data vektor berbasis kode (Lottie Files). Langkah ini berhasil memotong beban RAM hingga 75%.

Kepatuhan Regulasi UU PDP: Kami memasang filter pembersih data pribadi (Sanitization Layer) sebelum teks dikirim ke luar sistem untuk menjaga privasi isi curhatan pengguna.

8. Validasi Kebutuhan Berbasis Perilaku

Contoh skenario uji coba untuk menjamin kecepatan respon sistem (NF-2) sebelum dinyatakan selesai:

GIVEN: Pengguna menekan tombol kirim pesan curhat ke AI.
WHEN: Data payload diolah secara asinkronus oleh backend.
THEN: Komponen chat layar utama wajib memunculkan balasan dalam waktu kurang dari 5 detik.
